Transaction Execution Flow

  1. Role Lookup: Resolves AGENT role_id via subquery.
  2. Insert User: Inserts into users table and retrieves generated ID via LAST_INSERT_ID().
  3. Insert Agent: Uses the user ID as primary and foreign key to insert into agents.
  4. Atomic Commit: Both records commit simultaneously.
If step 3 fails (e.g., duplicate license), step 2 automatically rolls back.

Shared Primary Key Architecture

CREATE TABLE agents (
  agent_id        INT PRIMARY KEY,
  license_no      VARCHAR(50) NOT NULL UNIQUE,
  agency_name     VARCHAR(100),
  commission_rate DECIMAL(4,2) DEFAULT 2.50,
  bio             TEXT,
  hire_date       DATE DEFAULT (CURRENT_DATE),
  CONSTRAINT fk_agents_user
    FOREIGN KEY (agent_id)
    REFERENCES users(user_id)
);

agent_id serves simultaneously as primary key and foreign key, strictly enforcing 1:1 cardinalities.

Strict 3NF design eliminates redundant data between general users and agents.
