Trigger Implementation on properties

AFTER INSERT / UPDATE / DELETE 
-- Executed as 3 distinct triggers in MySQL:
CREATE TRIGGER trg_properties_ai AFTER INSERT ON properties ...
CREATE TRIGGER trg_properties_au AFTER UPDATE ON properties ...
CREATE TRIGGER trg_properties_ad AFTER DELETE ON properties ...

Triggers use NEW and OLD pseudo-records to log exact before/after transitions, such as "AVAILABLE->SOLD".

AFTER triggers fire only when mutations succeed. Any failed statement automatically rolls back without leaving spurious audit entries.

Password hashes are intentionally omitted from audit logs to maintain security.

Why Audit at the Database Level?

Application-level logging only captures operations initiated via the web app. Mutations performed via phpMyAdmin, shell scripts, or administrative consoles would be completely missed.

Database triggers cannot be bypassed. Regardless of the connection origin, audit records are written atomically within the same database transaction.
