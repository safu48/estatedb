Deletion Cascading & Integrity Protection

ON DELETE CASCADE vs. Foreign Key Restriction

Four dependent child tables link to properties via ON DELETE CASCADE, ensuring clean automated cleanup:

property_images Photos attached to this listing are purged
property_amenities Amenity junction links are removed
favorites Removed from customer saved lists
inquiries Customer inquiry messages are deleted

However, transactions deliberately enforces NO CASCADE. Completed financial transactions cannot be orphaned: 

Error 1451: Cannot delete or update a parent row:
a foreign key constraint fails (`estatedb`.`transactions`,
CONSTRAINT `fk_txn_prop` FOREIGN KEY (`property_id`))

Completed deal records can never be deleted. Attempting to delete a sold/rented listing is blocked directly by MySQL.

These integrity constraints are maintained by MySQL itself, enforcing consistency across both the web application and external SQL clients.
